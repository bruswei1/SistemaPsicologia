# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

SistemaPsicologia is a Java Swing desktop application (NetBeans/Ant `j2seproject`), built as the
**Sistema de Gestión del Departamento de Psicología** for the **Colegio Nacional E.M.D. San Roque
González de Santacruz** (students, appointments, psychological attention notes). Implemented so
far: login, role-based access, student records, appointment agenda, SOAP-based attention notes,
file attachments, a dashboard, and an official academic-structure (curso/sección/turno) selector.

**Terminology note (important, read before touching UI strings):** the rebrand from a generic
"paciente" (patient) system to this school's terminology was done **at the UI text layer only**.
Every screen a user sees says "Estudiante" (not "Paciente"), "Atención"/"Atenciones" (not
"Sesión"/"Sesiones"), "Cita" (not "Turno" — "Turno" is reserved for the Mañana/Tarde shift of the
academic structure), and role labels via `Tema.etiquetaRol()` ("Profesional de Psicología",
"Usuario autorizado", "Administrador/a"). **Java class/package names, DB table/column names, and
role values stored in the DB were deliberately left unchanged** (`Paciente`, `PacienteDAO`, table
`pacientes`, `sesiones`, `turnos`, roles `admin`/`psicologo`/`secretaria`, etc.) to avoid touching
JDBC/FK-sensitive code. Don't get confused seeing "Paciente"/"Sesión"/"Turno" in the source — that's
expected; only add new UI-facing strings using the school terminology, never the old clinic terms.

- Java target: 1.8 (`javac.source`/`javac.target=1.8` in `nbproject/project.properties`)
- UI: Java Swing with [FlatLaf](https://www.formdev.com/flatlaf/) (`FlatLightLaf`/`FlatDarkLaf`, toggle in `Configuracion`) as the look and feel, installed via `Vista.Tema.instalarLookAndFeelGuardado()` in every screen's `main()`. **There are no NetBeans `.form` files in this project** — every `Vista` screen, including `MenuPrincipal`, is hand-coded (`GridBagLayout`/`BorderLayout`), not editable in the GUI Form Editor.
- Persistence: raw JDBC against MySQL (no ORM, no connection pool). The single `Conexion.conectar()` class lives at `src/conexion/Conexion.java` (`package conexion;`); always write `import conexion.Conexion;` / `new conexion.Conexion()`.
- **Folder names must match package names exactly, including case** (`src/conexion`, `src/dao`, `src/modelos`, `src/util`, `src/Vista`). Until 2026-09-28 the first three were `Conexion`/`DAO`/`Modelos`: javac on Windows didn't care, but NetBeans' case-sensitive index stopped resolving those packages as soon as one of their files was edited, flagged ~20 files as broken and (with Compile on Save on) refused to run the project. On Windows a case-only rename needs two `git mv` steps (via a temporary name).
- Persistence layer: `dao`/`modelos` packages hold the more recently added screens' data access (`PacienteDAO`, `SesionDAO`, `TurnoDAO`, `UsuarioDAO`, `HistoriaPsicologicaDAO`, `AuditoriaDAO`); several `Vista` screens (`Agenda`, `Sesiones`) instead run their own inline JDBC/SQL rather than going through a DAO — check the screen itself before assuming a DAO method exists for what you need.
- Entry point: `Vista.Login` (`main.class=Vista.Login` in `nbproject/project.properties`)

## Build, run, test

This is a NetBeans Ant project. There is no Maven/Gradle wrapper.

- Build: `ant -f build.xml` (or open in NetBeans and use Build/Run — the Ant script `build.xml` just imports the NetBeans-generated `nbproject/build-impl.xml`)
- Run: `ant run` (runs `Vista.Login`, the configured main class), or run/debug directly from NetBeans
- No JDK with `javac` is guaranteed to be on PATH in this environment — only a JRE (`java`) may be present. Check before assuming you can compile from the shell; NetBeans itself has its own bundled JDK reference (`platform.active=default_platform`).
- No test framework/test sources exist yet (`test.src.dir=test` is configured but empty).

### Dependencies

Two external jars, both wired via `file.reference.*` properties + `javac.classpath` in `nbproject/project.properties` — there's no Maven/Gradle dependency manager:
- MySQL JDBC driver at `lib/mysql-connector-j-9.7.0.jar` and FlatLaf at `lib/flatlaf-3.5.4.jar`, both referenced with **project-relative paths** (`file.reference.*=lib/...`), so the project builds on another machine out of the box. Keep this `lib/` + relative-path pattern for any future dependency.

## Database

MySQL database name: `psicologia`. `src/conexion/Conexion.java` reads an optional `conexion.properties` from the working directory (`db.host`, `db.puerto`, `db.nombre`, `db.parametros`, `db.usuario`, `db.password`; see `conexion.properties.example`, the real file is git-ignored) and defaults to:
```
jdbc:mysql://localhost:3306/psicologia, user "root", empty password
```
`Conexion.conectar()` **never returns null**: if the server can't be reached it throws `Conexion.SinConexionException` (an `IllegalStateException` with a user-readable message); `DAO.obtenerConexion()` rethrows it as `SQLException`.

### Time zone rule

The MySQL server (Docker) runs in **UTC**, while every `DATETIME` the app writes (`turnos.fecha_hora`, `auditoria.fecha`, `sesiones.fecha`, ...) is the **PC's local time** (Paraguay, UTC−3), passed explicitly from Java. So never compare against `NOW()`, `CURDATE()` or `CURRENT_TIMESTAMP` in SQL — pass `Timestamp.valueOf(LocalDateTime.now())` / `LocalDate.now().atStartOfDay()` as a parameter instead (see `TurnoDAO.contarProgramadosVencidos`/`obtenerProximas`/`obtenerDelDia`, `Agenda.marcarVencidasComoAusente`).

### Local MySQL via Docker

`docker-compose.yml` at the project root runs MySQL 8.0 for local development, matching `Conexion.java` exactly (db `psicologia`, root, no password), so no code changes are needed to use it:
```
docker compose up -d
```
- Port 3306 is exposed on the host — **this conflicts with any locally-running MySQL** (this project's dev machine has XAMPP, whose `mysqld` binds 3306; stop it first: XAMPP control panel, or find/kill the process bound to port 3306).
- `db-init/*.sql` files are auto-executed by the MySQL entrypoint **only on first container/volume creation**. If the container/volume already exists, apply new SQL manually, e.g.:
  ```
  docker exec -i psicologia_mysql mysql -uroot --default-character-set=utf8mb4 psicologia < path/to/script.sql
  ```
- **Character set:** the `mysql` client inside the container defaults to `latin1`. Feeding it a UTF-8 file without `--default-character-set=utf8mb4` (or a `SET NAMES utf8mb4;` line) double-encodes every accent/ñ ("Técnico" → "TÃ©cnico"). Backups from `util.RespaldoBaseDatos` start with `SET NAMES utf8mb4;` since 2026-09-27; **older backups must be restored with `--default-character-set=utf8mb4`**. Restoring = create an empty DB, apply `db-init/*.sql`, then load the backup (it holds data only). This round-trip was verified byte-for-byte.
- Current schema: `db-init/01_schema.sql` creates `usuarios` (`id, usuario, password_hash, salt, nombre, rol, activo, creado_en`); `db-init/02_pacientes.sql` creates `pacientes` (`id, nombre, apellido, fecha_nacimiento, genero, telefono, email, direccion, motivo_consulta, psicologo_id, antecedentes_personales, antecedentes_familiares, anamnesis, creado_en`); `db-init/03_fase1_roles_historia_auditoria.sql` adds `usuarios.rol`, the `pacientes` clinical/ownership columns, and creates `auditoria` (`id, usuario_id, usuario_nombre, accion, entidad, entidad_id, detalle, fecha`); `db-init/04_fase2_agenda_sesiones_documentos.sql` creates `turnos` (appointments), `sesiones` (SOAP notes), and `documentos_paciente` (file attachment metadata); `db-init/05_historia_psicologica.sql` creates `historia_psicologica` (extended clinical history, one row per `pacientes.id`); `db-init/06_estructura_academica.sql` adds `pacientes.curso` (nullable `VARCHAR(100)`) — the single canonical label produced by `util.EstructuraAcademica`/`Vista.SelectorCursoSeccion`, see Architecture below; `db-init/07_ci_estudiante.sql` renames `pacientes.email` to `pacientes.ci` (`VARCHAR(20)`) — the "Nuevo Estudiante" form captures the student's cédula/número de identificación instead of an email address (`Modelos.Paciente.getCi()`/`setCi()`, not `getEmail()`).

### Auth model

Passwords are **not** stored in plaintext. `usuarios.password_hash` is `SHA-256(salt + password)` (hex), with a random 16-byte `salt` (hex) per user, implemented in `src/util/PasswordUtil.java` (`generarSalt`, `hash`, `verificar` — the latter is constant-time). There is no bcrypt/scrypt lib in the classpath by design (keeps the single-jar dependency minimal) — if stronger hashing is ever needed, that's a deliberate tradeoff to revisit, not an oversight.

To create a user manually (no registration UI yet), generate a salt+hash pair consistent with `PasswordUtil` (16 random bytes → hex salt; `SHA-256(saltHex + password)` → hex hash) and `INSERT INTO usuarios (usuario, password_hash, salt, nombre, rol) VALUES (...)`. `rol` is one of `admin`, `psicologo`, `secretaria`.

### Roles and session

`src/util/Sesion.java` is a static/global holder for the logged-in user (`usuarioId`, `usuario`, `nombre`, `rol`) plus `esAdmin()`/`esPsicologo()`/`esSecretaria()` helpers. `Vista.Login` populates it via `Sesion.iniciar(...)` right after a successful auth check and before opening `MenuPrincipal` — every other screen reads from `Sesion` statically rather than having the user passed through constructors. It is **process-global, not thread-local**: fine for this single-window desktop app, but don't assume it works if the app ever goes multi-session.

Role behavior implemented so far (in `GestionPacientes` and other screens querying `pacientes`):
- `psicologo` (shown to the user as "Profesional de Psicología", see `Tema.etiquetaRol`) only sees/queries students where `pacientes.psicologo_id = Sesion.getUsuarioId()`; the "Profesional asignado" combo in the student side panel is locked to themselves. `admin`/`secretaria` pick the professional there (or "Sin asignar"); a student with no `psicologo_id` is invisible to every professional, so the list flags it with the "Sin profesional asignado" alert.
- Exports must respect the same rules: `GeneradorReportes.generarCSVPacientes` drops the clinical "Motivo de atención" column for `secretaria`.
- `secretaria` (shown as "Usuario autorizado") is blocked from `Sesiones` entirely (menu button disabled in `MenuPrincipal`, SOAP-based attention notes are clinical/confidential).
- `admin` (shown as "Administrador/a") has full access, including reassigning `psicologo_id` on any student and managing user accounts in `Configuracion`.

### Auditoria

`src/util/Auditoria.java` (`Auditoria.registrar(Connection, accion, entidad, entidadId, detalle)`) inserts one row per action into `auditoria`, reading the actor from `Sesion`. Call it inside the same try-with-resources `Connection` as the operation it's logging (see `Login.autenticar` for `LOGIN`; `GestionPacientes` for `CREAR_PACIENTE`/`EDITAR_PACIENTE`/`VER_PACIENTE`/`ELIMINAR_PACIENTE`; `Agenda` for `CREAR_TURNO`/`EDITAR_TURNO`/`ELIMINAR_TURNO`/`COMPLETAR_TURNO`; `Sesiones` for `CREAR_SESION`/`EDITAR_SESION`/`VER_SESION`; `HistoriaPsicologicaView` for `VER_HISTORIA`/`EDITAR_HISTORIA`; `Configuracion` for account-management actions). The `accion` codes stay in Spanish/snake_case matching the internal entity names (`PACIENTE`, `SESION`, `TURNO`) even though the UI now says "Estudiante"/"Atención"/"Cita" — they're technical log identifiers, not user-facing copy, and `Configuracion`'s "Actividad reciente" viewer shows them raw. This is the app's "who accessed which record when" trail (good practice for minors' sensitive data and relevant to Paraguay's general data-protection Ley 7.593/2025, in force Nov 2027 — note that Ley 6534/2020 is about *credit* data, not health records) — extend it by calling `Auditoria.registrar` from any new screen that reads or writes student data, using the same `entidad`/`entidad_id` convention (table name, row id).

### Student file attachments

`documentos_paciente` stores attachment metadata; the files live on disk under `adjuntos/<paciente_id>/<timestamp>_<filename>` (never DB blobs), managed from the "Adjuntos (n)" tab of `DetallePaciente` (multi-file attach or drag-and-drop from Explorer, open, show in folder, delete, "Abrir carpeta" for that student; hidden for `secretaria`). `ruta_archivo` is stored **relative to `util.Carpetas.base()`** and must be read back through `Carpetas.resolver(...)`, never `new File(ruta)`. The `adjuntos/` folder is git-ignored runtime data — don't assume it exists on a fresh checkout.

### Data folders and exports

`util.Carpetas` is the single source for on-disk locations: `base()` is the working directory, or `Documents\Sistema Psicologia` when that isn't writable (e.g. installed under Program Files); `adjuntosDe(id)`, `reportesDe(id, nombre, apellido)` (`reportes/Estudiantes/<Apellido, Nombre (id)>/`), `listados()` (`reportes/Listados/`), `respaldos()`. It also has `nombreSeguro` (Windows-safe names), `archivoUnico`, `abrir`/`mostrarEnCarpeta`. Never hardcode `new File("reportes")` etc. Exports live in the `ReportesArchivos` tab (Estudiantes → "Reportes y archivos") plus "Exportar lista (Excel)" in `GestionPacientes` (exports exactly the filtered rows) — use `GeneradorReportes.exportarListadoEstudiantes(...)`, which writes and audits. After an export, show `Tema.mostrarArchivoGuardado(...)` (Abrir / Mostrar en carpeta) and log it to `auditoria` (`EXPORTAR_FICHA`, `EXPORTAR_NOTA`, `EXPORTAR_ESTUDIANTES`). CSVs are `;`-separated UTF-8 with BOM (Excel in Spanish locale) — write them with `GeneradorReportes.guardarTexto(..., true)`.

## Architecture

Five packages under `src/`:
- `conexion` — single class `Conexion.conectar()` opens a new `java.sql.Connection` per call (no pooling/singleton). Callers are responsible for closing it (use try-with-resources).
- `modelos` — plain data classes: `Paciente`, `Usuario`, `Sesion` (model, not to be confused with `util.Sesion`), `Turno`, `HistoriaPsicologica`.
- `dao` — JDBC access for the newer screens: `PacienteDAO`, `SesionDAO`, `TurnoDAO`, `UsuarioDAO`, `HistoriaPsicologicaDAO`, `AuditoriaDAO`, and the shared `DAO` base class (connection/logging helpers). Not every screen goes through a DAO — `Agenda` and `Sesiones` run their own inline JDBC instead (see below).
- `util` — cross-cutting helpers with no UI dependency: `PasswordUtil` (hashing), `Sesion` (current-user holder), `Auditoria` (access log writer), `ControlPermiso` and `Validador` (exist but are **not currently called** from any `Vista` screen — don't assume their rules are enforced; e.g. `Validador`'s password-length rule differs from what `Configuracion` actually enforces inline), `GeneradorReportes` (plain-text `.txt` fichas/notas and Excel-friendly `.csv` generation, plus `guardarTexto` — no PDF output), `Carpetas` (data-folder locations, see above), `EstructuraAcademica` (the closed, official catalog of curso/sección/turno for the school — grados 7°/8°/9° EEB and Bachillerato Técnico/Científico with their specific turno rules; this is the single source of truth for academic structure, extend it only if the school's actual course offering changes, never by guessing/adding plausible-looking options).
- `Vista` — Swing panels/frames. **There are no NetBeans `.form` files in this project** — every screen, including `MenuPrincipal`, is hand-coded with `GridBagLayout`/`BorderLayout`, not editable in the GUI Form Editor.
  - `Tema` — centralized palette/typography/spacing/icon-drawing helpers; every screen should use `Tema.*` instead of declaring its own `new Color(...)`/`new Font(...)`. Also holds the dark-mode toggle (persisted to `tema.properties`) and the role/estado display-label translation (`Tema.etiquetaRol`, `Tema.rendererRol`, `Tema.rendererRolCombo`, `Tema.etiquetaEstadoCita`, `Tema.rendererEstado`) — these translate the raw DB values (`admin`/`psicologo`/`secretaria`, `programado`/`completado`/`cancelado`/`ausente`) to the school-facing labels ("Profesional de Psicología", "Programada", etc.) **for display only**; the underlying value saved to/read from the DB is never translated. `PRIMARIO`/`SECUNDARIO` are the violet/blue pair taken from the Department's real banner (photo supplied by the user) — every screen's top banner is built with `Tema.panelEncabezado(titulo, subtitulo)` (a `SECUNDARIO`→`PRIMARIO` gradient bar) and every section border with `Tema.tituloSeccion(texto)` (a brand-colored `TitledBorder`) instead of calling `BorderFactory.createTitledBorder(...)` directly — keep using those two instead of hand-rolling a header or a plain titled border on any new screen.
  - `Login` — authenticates against `usuarios` via `PasswordUtil.verificar`, populates `Sesion`, logs `LOGIN` to `auditoria`, then opens `MenuPrincipal` and disposes itself. Installs the saved look-and-feel via `Tema.instalarLookAndFeelGuardado()` — the only place that happens for the real app flow.
  - `MenuPrincipal` — main menu shell (a single `JFrame` with a `CardLayout` swapping panels, not one `JFrame` per screen); title bar and header show the logged-in user/role. Three cards: "Estudiantes" (`EstudiantesPanel`), "Panel" (`Dashboard`), "Configuración" (`Configuracion`), plus the Ctrl+K search bar and the "Hoy" strip. Closing the window, logging out and reloading the shell (theme toggle, name change → `reconstruirVentanaSiSePuede`) all ask first if `EstudiantesPanel.hayCambiosSinGuardar()` (the close button is `DO_NOTHING_ON_CLOSE` + `salirDelSistema()`).
  - **Single-window rule:** nothing opens a new `JFrame`/`JDialog`. Sections swap inside `MenuPrincipal`'s `CardLayout`; secondary content (print preview, audit history, "archivo guardado", confirmations) uses `Tema.mostrarHoja(...)` / `Tema.confirmar(...)` — an in-window overlay (dimmed background + centered card, Esc closes the topmost). Keyboard shortcuts must be registered with `Tema.atajo(...)`/`Tema.atajoEscape(...)`, which only fire while the owning panel is showing and no hoja is open (plain `registerKeyboardAction(WHEN_IN_FOCUSED_WINDOW)` would also fire from hidden cards). `SelectorFechaHora`'s calendar is a hoja too. Remaining native popups by design: `JOptionPane` errors, `JFileChooser` and the OS print dialog. Toolbars that can get narrow use `Tema.compactarAlAchicar(barra, botones...)` (secondary buttons collapse to icon-only). Don't use Unicode glyphs like ◀ ▶ ✓ ✕ in labels — Segoe UI renders them as empty boxes; draw them as `Icono` values (`ANTERIOR`, `SIGUIENTE`, `CERRAR`, ...).
  - **Transitions:** switch cards only through `Tema.cambiarConFundido(ventana, contenedor, layout, carta[, haciaAtras])` — a time-based (300 ms, ease-in-out) crossfade + short horizontal slide between snapshots of the old and new card; pass `haciaAtras=true` when going back (to the menu, to the list). Hojas enter with a dim + slide-up (`Tema.mostrarHoja`). `MenuPrincipal.programarPrecarga()` builds Estudiantes/Panel/Configuración in the background while the user is idle on the menu (one per 2 s) so the first click doesn't stall ~0.6 s; keep new sections behind an `asegurarX()` + `mostrarX()` pair like the existing ones.
  - `PanelDeslizable` — reusable slide-in side panel (title/subtitle, X, scrolling body, fixed footer; `abrir()`/`cerrar()`/`estaAbierto()`), placed in the EAST of a BorderLayout. Used by `Agenda`; `GestionPacientes` has an older inline version of the same pattern. Use it for any new create/edit form instead of a form stacked above a table.
  - Tables: `Tema.estilizarTabla`'s renderer shows `Timestamp`/`LocalDateTime`/dates as `dd/MM/yyyy HH:mm` — put the date object (not a preformatted string) in the model so header sorting stays chronological. Disabled `Tema.boton*` buttons use a muted, theme-aware fill; check new screens in both light and dark mode.
  - `LineaDeTiempo` — chronological case timeline shown next to the datos in `DetallePaciente`'s "Información Personal" tab: atenciones, seguimiento entries, citas and adjuntos (metadata only, never note text; `secretaria` gets citas only), grouped by month with type filter chips; clicking an item selects/loads that record in its tab (`abrirEventoDeLineaDeTiempo`, respecting the unsaved-draft confirmation). Reloads whenever the tab is shown again.
  - `BloqueoPantalla` — screen lock owned by `MenuPrincipal`: after N idle minutes (per-PC preference `bloqueo.minutos` in `tema.properties`, chosen in Configuración → Preferencias; 0 = never) or Ctrl+L, an opaque layer above everything (registered via `Tema.registrarCapaModal`, so `Tema.atajo` shortcuts and hoja Esc are inert) asks for the user's password; nothing underneath is closed or lost. It does **not** auto-lock while an atención cronómetro runs (`EstudiantesPanel.hayAtencionEnCurso`). 5 wrong passwords → forced logout. "Cerrar sesión / otro usuario" warns in two steps if there are unsaved changes. Audited as `BLOQUEO_SESION`/`DESBLOQUEO_SESION`; cita reminders omit the student's name while locked. Local preferences go through `Tema.leerPreferencia`/`guardarPreferencia` (they merge keys; never rewrite `tema.properties` wholesale).
  - `ImportarEstudiantes` + `util.ImportadorEstudiantes` — "Importar desde Excel" in the student list: a hoja explains how to save a CSV from Excel (and can create a template), then a row-by-row preview (Se importa / con advertencia / No se importa + reason: missing name, CI already registered or repeated in the file, unknown curso, impossible date) with a "Profesional asignado a todos" combo before confirming. Reads `;`/`,`/tab, UTF-8 (±BOM) or windows-1252, quoted fields, header aliases without accents; round-trips the system's own CSV export. Each created student is audited `CREAR_PACIENTE` ("Importado desde …") plus one `IMPORTAR_ESTUDIANTES` summary.
  - `BusquedaRapida` — Ctrl+K from anywhere (and the search bar on the main menu): live, role-filtered student search in a hoja; ↑/↓ + Enter opens the ficha (Enter while still searching opens the first result when it arrives); shows the session's recently opened students when empty (`registrarReciente`, cleared on logout).
  - `EstudiantesPanel` — the "Estudiantes" section: tabs Lista de Estudiantes (`GestionPacientes`) / Agenda / Reportes y archivos (`ReportesArchivos`), plus a second card that shows `DetallePaciente` in place of the list (`abrirFicha`/`volverALista`).
  - `GestionPacientes` — student list/search/CRUD screen: a role-filtered table of `pacientes` with a curso filter combo, and a **slide-in side panel** ("Nuevo / Editar estudiante", `mostrarFormulario`/`cerrarFormulario`) with numbered sections, a completeness bar, inline validation, "Guardar y agregar otro", and a discard-changes confirmation (`formularioModificado`; set `cargandoFormulario` while filling fields from code). Double-click/Enter/"Ver ficha" opens `DetallePaciente` through the `setAlAbrirFicha` callback; `guardarPaciente` does an `INSERT` or `UPDATE` depending on `pacienteIdActual` and highlights the saved row (`idASeleccionar`).
  - `DetallePaciente` — student detail **panel** (a `JPanel`, not a window; constructor takes `alEditar` and `alCerrar`, call `cerrar()` or `salir(despues)` to leave — both stop the atención timer and ask before discarding an unsaved seguimiento/atención draft; "Nueva entrada"/"Nueva atención" and picking another row ask too): action bar (Volver a la lista, Editar datos, Adjuntar, carpetas) + `JTabbedPane` Información Personal / Seguimiento del Estudiante / Atenciones / Adjuntos.
  - (The former standalone `HistoriaPsicologicaView` and `Sesiones` screens no longer exist: seguimiento entries — `historia_psicologica`, one row per entry — and SOAP atenciones now live in `DetallePaciente`'s "Seguimiento del Estudiante" and "Atenciones" tabs. The descriptions of `Sesiones` below still apply to that tab.)
  - `SelectorCursoSeccion` — reusable `JPanel` with dependent combo boxes (Nivel → Grado+Sección or Año+Modalidad+Especialidad → Turno) backed entirely by `util.EstructuraAcademica`; it is structurally impossible to select a curso/turno combination that isn't in that catalog. Persists as a single canonical label string in `pacientes.curso` (e.g. `"9° EEB - Sección B - Turno Mañana"`); `EstructuraAcademica.parsearEtiqueta`/`construirEtiqueta*` convert between that string and the selector's UI state.
  - `Agenda` — appointment scheduling (`turnos`, shown to the user as "Citas"): the list/calendar takes the full width with an action bar (Nueva cita, Eliminar, Ver calendario); the create/edit form (estudiante, profesional, date/time, estado, notas) lives in a `PanelDeslizable` that opens on "Nueva cita" or when a cita row is selected, and closes after saving/deleting. Estado combo items are the raw DB values (`programado`/`completado`/`cancelado`/`ausente`) displayed through `Tema.rendererEstadoCombo()`; overlap warning; monthly calendar view. Filtered to the logged-in psicólogo's own students/citas. Runs its own inline JDBC (`PacienteItem`/`PsicologoItem` inner classes), not `PacienteDAO`/`TurnoDAO`.
  - `Sesiones` — SOAP-based attention notes (`sesiones`, shown to the user as "Atenciones") per student: the four SOAP fields are re-labeled for the school context ("Relato del estudiante (Subjetivo)", "Observación profesional (Objetivo)", "Análisis de la situación", "Acuerdos y recomendaciones (Plan)") plus `notas_privadas` ("Seguimiento y notas privadas"), and a simple start/stop cronómetro (`javax.swing.Timer`) that records `duracion_minutos`. Saving a note linked to a `programado` cita auto-marks it `completado`. Not reachable by `secretaria`. Also runs its own inline JDBC, independent of `SesionDAO`.
  - `Dashboard` — aggregate counts only (never raw clinical text): estudiantes/atenciones/citas/profesionales tiles, a comparison bar chart, a 6-month new-students trend, and an "Estudiantes por curso" table (`PacienteDAO.contarPorCurso`). It is **navigable** through `Dashboard.Navegacion` (set by `MenuPrincipal`): tiles lead to the list/agenda, "Estudiantes por curso" rows open the list filtered by that curso (`EstudiantesPanel.mostrarListaFiltrada`), "Próximas citas"/"Seguimientos vencidos" rows open the student's ficha (DAO rows carry `pacienteId`).
  - `ResumenDelDia` — the "Hoy" strip on the main menu: today's citas (`TurnoDAO.obtenerDelDia`, own citas for `psicologo`) as clickable chips (open the ficha), next one highlighted with "en X min", "Ver agenda". `MenuPrincipal` also shows a welcome toast with today's count and polls once a minute (plain `SwingWorker`, no wait cursor) to remind 10 minutes before each programmed cita; the timer stops on logout.
  - `ReportesArchivos` — "Reportes y archivos" tab of `EstudiantesPanel` (the main menu keeps exactly 3 cards: Estudiantes, Panel, Configuración): quick-action tiles (`TarjetaAccion`) for export CSV / backup / open folders, and a live-filtered, sortable list of generated documents under `reportes/` (per-role: `psicologo` only sees their students' folders, `secretaria` only listados).
  - UI conventions for new/edited screens: actions that need a selected row live in a toolbar above the table and are enabled/disabled via the selection listener; tables get a right-click menu (`Tema.seleccionarFilaConClicDerecho`) and Enter/Supr bindings; search fields filter while typing (`Tema.alEscribir`); **always convert the selected view row with `tabla.convertRowIndexToModel(...)` before reading the model** — `Tema.estilizarTabla` enables header sorting. Main menu has Alt+1…3; `DetallePaciente` has Ctrl+S/Ctrl+E (acts on the visible tab) and Ctrl+1…4; `GestionPacientes` has Ctrl+F/Ctrl+N. The "Nuevo/Editar Estudiante" side panel starts hidden; Esc/Ctrl+Enter close/save it.
  - `Configuracion` — own-account settings (name, password) for everyone; for `admin` only, adds user management (create/reset-password/activate-deactivate/delete/change-role — role combos use `Tema.rendererRolCombo` for display but submit the raw role value) and an "Actividad reciente" `auditoria` viewer (text/date-range filter, pagination via "Cargar más antiguos"). Also has the dark-mode toggle (exports/folders moved to `ReportesArchivos`).

When adding new screens, follow the existing pattern: JDBC access via `new conexion.Conexion().conectar()` wrapped in try-with-resources, `PreparedStatement` for all queries (no string-concatenated SQL — the codebase is consistent about this), read the actor from `Sesion` rather than re-querying `usuarios`, log mutations/views to `auditoria` via `Auditoria.registrar`, use `Tema.*` for styling instead of ad-hoc colors/fonts, and use the school terminology ("Estudiante", "Atención", "Cita", role labels via `Tema.etiquetaRol`) in every new user-facing string — never "Paciente"/"Sesión"/"Turno"/"Doctor"/"Clínica" in anything the user reads.
